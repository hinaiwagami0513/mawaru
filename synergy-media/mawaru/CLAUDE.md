マワル = SNS投稿管理 + AI生成 SaaS（Instagram / X / TikTok / YouTube）。
Stack: Next.js + Tailwind CSS v4 + shadcn/ui + Tabler icons。`DESIGN.md` から globals.css を生成、手で触らない。
ワイヤーHTML群は `mawaru_board/`（`board.html` がエントリ、`flow_*_wire.html` が各フロー）。

すべて `synergy-media/mawaru/` 配下で完結する。他グループ（honeytouch / smart-lottery / green-upcycle / ship-inc）のファイルは読まない・流用しない（ルート `CLAUDE.md` の跨ぎ参照禁止）。

## 日次の作業ログ

その日やったことは `mawaru-vault/raw/worklog-YYYY-MM.md` に**新しい日を上に**足す。取引先共有の原本。
素材は `tools/collect-worklog.sh [YYYY-MM-DD]` でその日のコミット・差分・未コミット変更を出してから書く。
**公開リポジトリなので報酬・請求・契約と社外秘の議題は書かない。**

## 知識の引き方

- 設計・仕様の詳細は `mawaru-vault/` にある。まず `mawaru-vault/INDEX.md` を読み、必要なページだけ開く。全読みしない。
- 画面/機能 → `mawaru-vault/entities/`、判断/パターン → `mawaru-vault/concepts/`、一次情報 → `mawaru-vault/raw/`。
- ※ 旧 `mawaru-knowledge.md` は vault 化済み。古い値が残っているので単体で参照しない。

## 裁定ルール（矛盾したらこれ）

- デザイン（色・角丸・タイポ・トークン・部品）は `DESIGN.md` が唯一の源泉。
- プロダクト仕様は最新の会議 / worklog が正。
- 迷ったら `mawaru-vault/concepts/superseded.md`。旧仕様（Tailwind禁止・C.pr短縮名・絵文字SNS・角丸28・weight800 等）を復活させない。

## 画面を作る・直すときの判断基準

実装が正しいことと、受け取った人が使えることは別。ここは後者だけを見る。
**案を出した直後（実装前）と、完了報告を書く前**の2回通す。

### 1. 一箇所直すなら、同じ問題のある画面を全部洗い出して揃える

画面ごとにやり方が違うと、使う人が画面ごとに覚え直すことになる。目の前の1件だけ直して終わりにしない。

- 直す前に `mawaru_board/*.html`（現在34枚）を grep で数え、**対象一覧を出してから**直す。位置・文言・順序も揃える
- 全部直せない事情があるなら、**直していない画面を名指しで報告する**。黙って一部だけ直さない
- 「今回のスコープ外」で残していいのは、残した画面を報告に書いた場合だけ

### 2. 初めて触る人の目で見る

納品先が迷うと、機能があっても使われないまま終わる。判断材料から「自分は使い方を知っている」を外す。

- その画面に初めて来た人が、**次に何を押せばいいか分かるか**
- 専門用語を画面に出していないか。文言の源泉は `DESIGN.md` §Writing と `mawaru-vault/concepts/wording-level.md`
- 説明を足して解決しない。足りないのは説明ではなく名前（`mawaru-vault/concepts/no-in-card-help-text.md`）

### 3. 迷う・消える は、機能が揃っていても欠陥として扱う

仕様どおり動くかではなく、**触った人が詰まるか**で見る。次は欠陥とみなす。

- 入力したものが、戻る・タブ切替・サイドバー遷移で消える
- 今どこにいて、どこへ戻れるのか分からない（パンくず・戻り先）
- 操作したのに一覧が更新されない

ワイヤーHTMLでも実際にブラウザで触って確かめる。ブラウザの戻る（トラックパッドの右スワイプを含む）まで試す。

### 4. AI が作った画面に見える表現を使わない

飾りで意味を作らない。意味は配置・既存の部品・文言で表す。禁止の本体は `DESIGN.md`、両方見る。

- カードやセクションの左に付けるアクセントライン。色で種類を表そうとしない
- 絵文字をアイコン代わりにする（Tabler icons を使う）
- グラデーション、全カードへの影、過剰な角丸（`mawaru-vault/concepts/depth-and-rhythm.md`）
- 情報量に見合わない中央寄せの大見出し
- 「✨」「🚀」のような装飾記号を文言に混ぜる

### 5. 変更した画面のスクリーンショットを毎回出す

文章の仕様説明より、実物を見た方が違和感に気づける。

- 見た目が変わったなら Before / After の両方。新しい画面なら After だけでよい
- 複数画面を触ったなら全部。代表1枚で済ませない
- 出せない理由があるなら、その理由を書く。黙って省略しない

### NEVER

- **一部だけ直して「対応しました」と報告しない。** 残した画面があるなら書く
- **実際に触らずに「問題なし」と書かない。** 確認していないものは「未確認」と書く
- **飾りを足して問題を解決しない。** 線・色・影で意味を作るより、配置と文言を直す
- **専門用語で報告しない。** 読むのはエンジニアではない。困りごとから書く
- **ここでコードの正しさを判定しない。** それは `/review` `/code-review` の担当

## vault の更新手順（議事録を渡されたとき）

1. 議事録は `mawaru-vault/raw/mtg-YYYY-MM-DD-〇〇.md` に原文尊重で追加（raw は書き換えない）。
2. そこで刷新・変更・廃止された点を洗い出し、波及する `entities/` `concepts/` を更新。
3. 旧方針をひっくり返した箇所は `concepts/superseded.md` に「旧 → 新」で追記。
4. 新規ページを作ったら `INDEX.md` に1行追加。
5. 最後に「どのファイルをどう変えたか」の差分サマリを出す。

## 書き込みルール

1ファイル1トピック・先頭に1行サマリ / 重複を作らず既存を更新 / 間違いは消すか superseded へ /
`raw/` は書き換えない / compiled ページは必ず raw のソースにリンクで裏取り。
