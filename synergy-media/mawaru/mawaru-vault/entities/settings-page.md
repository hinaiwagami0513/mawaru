## SNS設定の文言と行の作り（2026-08-20）
SNS接続の語は**「連携」で統一**（旧「つなぐ / つなぎ直す / つながっています」）。対応表は DESIGN.md §Writing、
旧→新は [[superseded]]。ヘルプセンター（`help_site/content/`）が元から「連携」で書かれていたのに合わせた形。

- 状態バッジ: **連携済み**（success + `ti-check`）/ **未連携**（中立の面+枠。異常ではないので状態色を使わない）。
- **「再連携」は正常な行に置かない。** ⋮ メニューに入れ、連携が切れた行だけ行内ボタンで出す。
  常時置くと「切れているのか？」と毎回読ませてしまう。news_wire.html の説明とも一致する。
- 行のレイアウト: PCはバッジ列(92px)と操作列(118px)を固定して**バッジを縦に揃える**（後ろが ⋮ かボタンかで幅が変わる）。
  SPはバッジと操作を2行目に落とし、バッジをSNS名と左揃えにする。実装 `mawaru_board/settings_wire.html`。

## メンバーを招くダイアログ（2026-08-30 追加）
「メンバーを招く」ボタンに導線が無かった（押しても何も起きない状態）。

- 入力を伴うので `alertDialog`（sonner）ではなく、`dlgGoal` と同じ自前ダイアログの形。
  閉じ方は ×／背景クリック／Esc の3系統を `openDlg` / `closeDlg` がそのまま持つ。
- 中身は **メールアドレス1件 + できること（権限）**。
- **権限はネイティブ `<select>` ではなく `.picks` を1列で積む。**
  表の行では「決まった権限を選び直す」だけなので select でよいが、招くときは**まだ何を選べばいいか
  分かっていない**ので、3つの説明を並べて見比べられる形にする。
  文言は下の `.rolehelp` と同じものを使う（言い方を増やさない）。
- 送ると一覧に**「招待中」の行が増え、人数も動く**。押した結果が画面に出ないと、
  送れたかどうかをトーストだけで判断させることになる。
- メール未入力はダイアログ内に赤字を増やさず、トーストで返して欄へフォーカスを戻す。
- 開いたら入力欄にフォーカス。DESIGN.md §alert-dialog は「取り消し側に置く」だが、
  ここは入力が主なので書く場所へ置く。Esc と背景クリックで抜けられるので逃げ道は塞いでいない。
- 実装 `settings_wire.html`（`#dlgInvite` / `openInvite()` / `inviteSend()` / `addInvitedRow()`）。

## アカウントの中は2タブ（2026-08-30）
`投稿ルール`（既定）/ `アカウント情報` の2タブ。**設定するものと読むだけのものを混ぜない。**

一度アカウント情報を「投稿ルール」の見出しの下に積んだところ、
陽菜「投稿のルールみたいな感じに書いてあるのに、下にアカウント状況があるのが変な感じ」の指摘。
AIの読み取り結果がルールの1つに見えていた。**旧UIも `ルール / アカウント情報 / 設定` のタブ構成**だったので、その形に戻った形。

- 既定は **投稿ルール**。ここは設定画面で、開く用は「決めごとを直す」ため。
  状況を見に来る導線は [[analysis-pages]] が持っている。
- 部品は運用目的の `.ptabs` をそのまま使う（画面ごとにタブを自作しない / [[component-procurement]]）。
- **見出しはタブが持つ**ので、カード側に「アカウント情報」を重ねて書かない。
  使いどころ（`.pj-use`）と操作（読み直す）は、ルールタブの `.rulebar` と同じ形で中身の上に出す。
- 実装 `settings_wire.html`（`.ptabs` / `#spRule` / `#spInfo` / `setSTab()`）。

## アカウント情報カード（2026-08-30 追加）
旧UI（`設定 > SNSアカウント > アカウント情報`）にあって新UIに無かった機能。
旧版は見出し11本・箇条書き100行超の**文章の壁**だったので、そのまま移さず作り直した。

**入れるのは「AIの理解」だけ。** 成績・改善案・目標は [[analysis-pages]] の担当なので持ち込まず、
末尾の「くわしい成績は『分析』で見る」で送る。同じ情報を2箇所に置かない。

| 節 | 形 | 中身 |
|---|---|---|
| どんなアカウントか | キツネ + 大きい文字1行 | 一言 + 補足1文（開設からの月数を含む） |
| いまの状態 | 回っているかの目印 + 数値タイル4枚 | 判定 / 出した投稿 / フォロワー / いまのペース / 反応された割合 |
| よく出しているもの | 構成比バー + 凡例 | 上位4カテゴリ + その他 |
| 投稿のかたち | ピル3枚 | 写真 / 動画 / 文字だけ の割合 |

### 回っているかの目印（`.ai-now` / 2026-08-30）
「今回っているのか、もう一踏ん張りなのか」を一目で言い切る（陽菜要望）。
**基準はこの画面の「1週間に出す本数の目標」**＝ユーザー自身が決めた数字。作り物の物差しを持ち込まない。

| 状態 | いつ | 出すもの |
|---|---|---|
| `ok`（既定） | 目標を満たしている | ✓ いい調子で回っています |
| `care` | 目標に届かない / 間が空いている | ⚠ もう一踏ん張りです |

ヘルプマークを足さずに読めるよう**3段重ねる**。
1. 判定を文で言い切る → 2. 根拠を1文で出す（「目標は週1本。直近8週のうち6週で出せています」）→ 3. 同じことを絵でも出す（8週ぶりのマス）。
2 が 1 の理由になっているので、3 のマスが何かは説明しなくても読める。

- **地は状態色にしない。** すぐ下の数値タイルと同じ中立の面 + 枠にする。
  `success-subtle` を敷いた版も作って見比べたが、状態色の帯はキツネアラートと見分けが付かず、
  アラートを自作したことになる（DESIGN.md「`.note` のような自前バナーを増やさない」）。
  丸アイコンとマスの色だけで十分読める。
- **キツネは足さない。** カード先頭にもう1匹いて2匹になる。
- 状態は色だけで表さない（アイコンと判定文が形を担う / [[state-color-plus-glyph]]）。

- **成熟度バッジ（「育ちはじめ」）は置かない**（陽菜判断 2026-08-30）。一度実装したが外した。
  段階の定義がどこにも無く、隣の数値タイル（86件・月4件ペース）以上のことを言っていない。
  「これは何？」となるのでヘルプマークを足す案が出たが、**説明しないと伝わらない要素は書き足さずに消す**
  （[[no-in-card-help-text]] / DESIGN.md §Writing 原則4）。開設からの月数は事実なので説明文に残した。
  ⚠️ 成熟度・ランクを再提案する前にこの行を読む。
- **読むだけ。編集ボタンは置かない**（陽菜判断 2026-08-30）。ズレていたら資料を足して「読み直す」を押す。
  他のカード（言葉づかい・推奨ワード）が「こう書いてほしい」の指示なのに対し、こちらは「AIは今こう読んでいる」の答え合わせ。
- 置き場所は `アカウント情報` タブ。`.bento` の先頭に置いていたが、ルールの1つに見えるのでタブに分けた（上記）。
- 構成比バーは `--chart-1..5` のオレンジ単一色相ランプ。系列は5を超えるとランプが破綻するので
  **上位4つ + その他**に畳む。名前直置き・実数と割合・構成比バーの3つで読ませる（[[chart-single-hue-ramp]]）。
- 使いどころは `.pj-use`、出どころは `.byai` と、他のカードと同じ部品に寄せた。
  カードの中に「〜するときに使います」を書き足さない（[[no-in-card-help-text]]）。
- 実装 `mawaru_board/settings_wire.html`（`#pj-acct` / `.ai-*`）。

### ⋮ メニューの中身（2項目で確定）
| 項目 | 何をする | 根拠 |
|---|---|---|
| 再連携 | そのSNSの認証画面へ飛ばす。マワル側に入力欄は作らない | `help_site/content/start.ts` 「SNS側でパスワードを変更したら、マワル側も連携し直す」「SNS側でアカウントを切り替えてから、再度連携」 |
| 連携を解除 | 確認ダイアログを経て解除。行は未連携の見た目に変わる | `help_site/content/start.ts` `settings.ts` 「一度連携を解除して、もう一度連携し直してください」 |

「アカウント切り替え」はヘルプ上「解除 → 再連携」と同じ操作なので別項目にしない。3つ目の候補はヘルプにも無い。

**連携解除はボード全体で唯一の導線**（実装前は解除操作がどの画面にも無かった。ヘルプは2箇所で案内していたのに画面が無い状態）。
確認ダイアログは `flow_video_script_wire.html` のシーン削除と同じ部品（`.cfmask`/`.cfbox`）を流用（[[component-procurement]]）。

⚠️ **未確定**: 解除したとき**予約している投稿をどう扱うか**（自動で下書きに戻す / 当日エラーにする）が
ワイヤーにもヘルプにも書かれていない。ダイアログは「予約している投稿は出せなくなります」で仮置き。決まったら差し替える。

## プランは設定でなく画面上部に出す（実装済み・2026-08-19）
ワイヤーに反映済み。**料金一覧は `mawaru_board/plan_wire.html` の独立ページ**になり、設定からは消えた。
ヘッダーのプランチップが `<a href="./plan_wire.html">` になっている（全ワイヤー共通）。
チップの塗りはオレンジにしない。押せる合図はホバー時の枠オレンジだけ（[[orange-only-interaction]]）。

「プランがどこから見られるか分からない」という声が多い（奥澤「プランどこから見れるんですかって聞かれる方があって、意外とみんな分からない」）。
- 上部の通知アイコン群（ベル / `?`）の近く、またはアカウント名の横に**バッジ**で常時表示。
- ラベルは「ベーシック」等ではなく**今のプラン内容が分かる名前**にする（佐藤）。
- **バッジを押すとプランページへ遷移**する（佐藤の提案）。
- ⚠️ 右上は要素が増えやすい。ニュース（ベル）と統合して数を抑える。

## 運用目的（旧プロジェクト管理）の作り
- 開閉式。資料を読み込ませると内容を自動生成し、**足りない項目は空欄のまま「書いた方がいいですよ」と出す**。
- 「今の情報だとこれくらい生成できる」という例も並べて出す。
- 文章をだらだら書かせず、**項目で分けて書かせる**（8/19に「めっちゃ分かりやすくなった」評価）。
- 「毎回必ず読みます」という但し書きを添える。
