# editing-surfaces（編集系の画面群）

> 画像編集ルーム / 動画作成ルーム / 投稿編集ページ。ルーム概念は廃止だが画面自体は残る([[room-concept-abolished]])。

## 画像編集ルーム（ImageEditRoomPage）
2フェーズ: 画像選択→編集(3カラム)。左ツール9種+AIチャット / 中央プレビュー+編集履歴 / 右パネル。
ヘッダー右「保存時に3pt消費」（編集ごとでなく保存時まとめて）。
素材選択は2系統: 投稿から選ぶ / アップロード+マワルドライブ（[[mawaru-drive]]）。

## 動画作成ルーム（VideoCreationPage）
3カラム: 左AIチャット / 中央9:16プレビュー+タイムライン / 右タブ(台本/素材/設定)。「生成時5pt消費」。

## 投稿編集ページ（PostEditPage・3カラム）
左プレビュー+編集ルームへ導線 / 中央編集(写真/投稿文タブ・画像台本アコーディオン) / 右AIチャット常駐。
手動投稿はここで完結。★タスク登録メニューは削除方向。

## 簡易エディター vs 完全版エディター（6/19確定）
- **簡易エディター**: 40-50代未経験者向け。直感的操作、最小限の機能に絞る。
- **完全版エディター**: スキルのある人向け。従来のフル編集機能を維持。
- 棲み分けを明確にし、初心者が完全版に迷い込まない導線設計が必要。
- 出典: [[raw/mtg-2026-06-19-iwagami]] / 関連 [[target-first]]

## スタイル / エフェクトはCapCut準拠（8/19確定）
機能の格納場所が見つけにくい問題（岩上「まだ分からないうちは全部とりあえず開ける。アーチにしたい、どこだ？」）に対して、
独自整理ではなく**CapCutの並びに一旦全部揃える**で決着。大半のユーザーが既に触っているツールに合わせるのが最短。

| | 定義 | 調整 |
|---|---|---|
| エフェクト | 動きを伴うプリセット。キラキラ・イラストっぽい装飾 | CapCutでは色も濃さも変えられない |
| スタイル | 個別に調整できる装飾。曲線・スペース・ストローク・シャドウ・タイピング風 | 個別に調整可 |

- **CapCutで不便な点はこちらで直してよい**（岩上）。例: エフェクトの色を変えられるようにする。
- 現状の「エフェクト」は「スタイルのプリセット」と中身が被っている。**エフェクト側を作り直す**。
- テキストの出方（1文字ずつ出る等）はスタイル側の扱い。
- 「しまい込んでスクロールで探させる」案は却下。CapCutの分類のまま覚えてもらう。
- 出典: [[raw/mtg-2026-08-19-iwagami]]

## SNS確認画面のセーフティゾーン（8/21）
SNSプレビュー（「SNSで見る」）に**左右の点線も足す**。上は既に点線があるので、左右を足して**センタリング確認に使える枠**にする。
奥澤「こっち側も一応セーフティゾーンで、ここも中心にちゃんと映ってるかなっていうのを確認する場所としてはすごいいい」。

## SPの畳み方（8/27）
編集面はどれもPCが3カラムなので、390pxでは**畳み方を決めておかないと中央カラムが数十pxまで潰れる**。

| 画面 | PC | SP（390px） |
|---|---|---|
| 投稿編集・フローの「投稿を編集」 | 左240 プレビュー / 中央1fr / 右auto AIパネル | 縦積み。AIパネルは全幅で最後 |
| 画像エディタ（ダーク） | 左ツール / 中央プレビュー / 右パネル | 縦積み。ツールは横スクロールの帯 |
| 動画エディタ（ダーク） | 左レール+プロパティ（absolute）/ 中央ステージ / タイムライン | **absolute を静的に戻して**縦積み |

- 実装は `mawaru_board/editor-sp.css`（フロー4種 + 投稿編集が読む共通ファイル）。`shell-sp.css`（サイドバー型）・`topbar-sp.css`（上部バー型）と同じ「レイアウト型ごとに1ファイル」の形。
- ダークエディタ2枚はファイル内の `@media (max-width:430px)` で持つ（構造が他と別物なため）。
- 効かせ方は**クラスに当てる**（`.ed-head` / `.ed-cols` / `.ed-tabs` / `.ed-panehd` / `.ed-typerow`）。`[style*="grid-template-columns:240px"]` のような属性セレクタは、インラインstyleを書き換えた瞬間に黙って外れるので使わない。
- 定型の判断: 表は列を潰さず横スクロール / タブは余白を詰めて入らない分を横スクロール / ボタンのラベルは折り返さない / 状態表示（自動保存ずみ等）は行を譲る。
- 出典: [[raw/worklog-2026-08]]（8/27）
