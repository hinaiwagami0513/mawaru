# no-in-card-help-text

> カードの中に説明文・使い方・見本を置かない。伝わらないなら書き足すのではなく名前を直す。

## 決定（2026-08-24・陽菜指示）

設定画面のカードから、次の3種類を全部落とした。

| 種類 | 例 | 判断 |
|---|---|---|
| 使い方 | 「投稿文のはじめの一文をつくるときに使います」 | 消す |
| 手順・お願い | 「お店のことが分かるURLやPDFを入れてください」 | 消す |
| 見本 | 「書き方の例」ブロック | 消す |
| 見出し直下の言い換え | 「このSNSだけの決めごとです」 | 消す |

残したもの:
- **選択肢を見分ける一文**。`やさしい`＝「〜ですよ」/ `ていねい`＝「〜いたします」。消すと選べなくなる。
- データ（`@inucafe_one・2026/06/12 に連携`）、ラベル（`フォロワー`）、状態（`AIが資料から作りました`）。

逆に、**数字で自明な選択肢の説明は消す**。`週1本`に「まずは慣れるところから」は不要。

## なぜ

カードが8枚並ぶ画面で1枚ずつ説明が付くと、**読む量が中身より多くなって主役が埋もれる**。
運用目的の画面は、4項目に対して「使い方ピル4個 + 進み具合の案内 + 資料の説明 + 書き方の例」が乗り、
実データより解説のほうが面積を取っていた。

説明を足したくなるのは、たいてい**見出しの名前が悪い**サイン。
`プロジェクト管理` → `運用目的` に変えたら説明が要らなくなった、というのが元の成功例（[[../DESIGN.md]] §Writing 語彙表）。

## 画面全体にかかる注意はどうするか

キツネアラート**1つ**に寄せる。カードごとにばらまかない。
例: 運用目的の「ここに書いたことは、AIが投稿を作るとき毎回かならず読みます」（ATTENTION）は残す。

**その1つは×で閉じられるようにする（2026-08-30）。**
寄せた1つは据え置きなので、一度読んだ人にも毎回同じ文が居座る。ドライブの ATTENTION は
SPで本文6行ぶんを占め、ファイル一覧を押し下げていた。読み終わった人が自分で片付けられる
逃げ道を1つ置く。消すかどうかは本人の任意で、既定は出したまま。
実装は `mawaru_board/fox-alert.js`（HTMLに×を書かなくても全画面に付く）。仕様は
[[../DESIGN.md]] §Alert。画面の中身そのものになっているアラート（投稿ごとのAI講評、
押した結果の報せ）は `data-keep` で対象外にする。

## 失効させたもの

DESIGN.md の Do's にあった
「説明・ヒントのチップは `primary-subtle` 背景 + `primary` 文字で出す」は**この決定で失効**。
色を選ぶ前に、その一文が要るかを疑う。記録・推し情報のチップだけオレンジで残す。
