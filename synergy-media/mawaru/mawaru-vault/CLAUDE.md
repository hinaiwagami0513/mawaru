# CLAUDE.md — マワル vault の使い方

> このファイルは毎回自動で読まれる「常時課金される税金」。だから薄く保つ。
> 中身はvaultに置き、ここは**指すだけ**。200行を超えたら削る。
> Cursorで使う場合はこの内容を `.cursor/rules/` か Project Rules に写す（役割は同じ）。

## この vault は何か

マワル（SNS投稿管理 + AI生成 SaaS）の設計・仕様ナレッジをAIが読んで作業に使うための外部記憶。
`mawaru-knowledge.md`（852行）と `DESIGN.md` を、育てられる4フォルダ構造に割ったもの。

## 作業前に読むもの

1. まず [[INDEX]] を開いて「何があるか」を把握。必要なページだけ開く（全フォルダ一気読み禁止）。
2. 画面・機能の仕様 → `entities/` の該当ページ。
3. 判断の根拠・パターン → `concepts/` の該当ページ。
4. 「なぜこう決めたか」の一次情報 → `raw/` を辿る。

## ⚖️ 裁定ルール（矛盾したらこれ）

- **デザイン（色・角丸・タイポ・トークン・コンポーネント）は DESIGN.md が唯一の源泉**。
  knowledge.md の古い値（`C.pr`短縮名・絵文字SNS・角丸28・weight800 等）は失効。詳細は [[superseded]]。
- **プロダクト仕様は最新の会議/worklog が正**（[[raw/mtg-2026-05-31-keisuke]] → [[raw/worklog-2026-06-03-04]]）。
- 迷ったら [[superseded]] を見る。ここに載る旧表現を復活させない。

## 書き込みルール（4つだけ）

1. 1ファイル1トピック。先頭に1行サマリ。
2. 重複を作らず既存を更新する。
3. 間違いと分かったノートは消す（or [[superseded]] に落とす）。
4. `raw/` は絶対に書き換えない。整理結果は entities / concepts に書く。

## 出力を「マワル仕様」にする下敷き

- 色・角丸・タイポは必ずトークンから引く（[[design-tokens]] / [[orange-only-interaction]]）。
- 状態は色だけで表さない、色+形/アイコン（[[state-color-plus-glyph]]）。
- shadcn部品を手で再発明しない（[[component-procurement]]）。
- 主張は必ず `raw/` のソースに紐づける。裏取りの無いページは信用しない。
