マワル（SNS投稿管理 + AI生成 SaaS）の**その日の作業ログ**を1日分だけ書く。
取引先（実装担当）が読む記録なので、何をやったか・何が良くなったかが分かる書き方にする。

## 入力

このあとに `---- ここから素材 ----` が来る。中身は:

- その日の git コミット（件名は英語、本文は日本語で詳しい）
- 差分統計と変更ファイル一覧
- 未コミットの変更（ファイル一覧 + diff の先頭）

素材は `## メインリポジトリ` と `## ワークスペース: 名前` に分かれていることがある。
作業がどのリポジトリや worktree で行われたかは記録の対象ではないので、**全部を1日分として
まとめて書く**。リポジトリ名・ワークスペース名・worktree 名は出力に出さない。

## 出力

**md のセクション本体だけを出す。** 前置き・後置き・挨拶・「以下が〜です」は書かない。
1行目が `## ` で始まり、最後の行が本文で終わること。コードフェンスで囲まない。

書式はこれに厳密に合わせる（この形を機械で読んでスプレッドシートに転記している）:

```
## YYYY-MM-DD（曜）

### やったこと

**まとまりの見出し**
- 具体的にやったこと
- 具体的にやったこと

**別のまとまりの見出し**
- 具体的にやったこと

### 直した不具合
- 何がどう壊れていて、どう直したか

### 見つけた不具合（未修正）
- 何が壊れているか。直していないことが分かるように

### 次にやること
- 残っていること
```

- 1行目は `## YYYY-MM-DD（曜）` で**終わる**。素材の見出しにある「マワル 作業素材」は付けない。
  日付と曜日の値だけを素材の見出しから取る。
- `###` の節は**中身があるものだけ**出す。空の節は作らない。
- `**まとまり**` は `### やったこと` の中だけで使う。他の節は `- ` を直接並べる。
- 箇条書きは1行1件。改行して折り返さない（機械が1行=1レコードとして読む）。

## 書き方

- **コミット本文に書いてあることを軸にする。** 素材に無いことを推測で足さない。
- 未コミットの変更から書いた項目は、行末に `（未コミット）` を付ける。
- ファイル名・色コード・数値は残す。取引先が実装するときの手がかりになる。
- 「対応した」「改善した」で終わらせず、**何がどうなったか**を書く。
  悪い例: 投稿フローを改善した
  良い例: 選択肢が1つだけの画面は選ぶだけで次に進む方式に変更（「次へ」ボタンを非表示）
- 1日分で 25 行を超えそうなら、細かい項目はまとまり単位に畳んで数を減らす。
- 敬語は使わない。体言止めか「〜した」で揃える。

## 書かないもの

- **報酬・請求・契約形態・社内検討**。このリポジトリは公開配信されている。
- グリーンアップサイクル / ハニタッチ / スマート抽選 / SHIP の話。マワル 以外のグループは混ぜない。
- コミットハッシュの羅列。必要なら「コミット4件」のように数だけ。
- 素材にあった diff の生テキスト。
